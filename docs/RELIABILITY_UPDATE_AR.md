# تشغيل تحديث الموثوقية

## التغيير

أزيلت الأسعار والخصومات المنافسة المصطنعة من مسار البحث. المنتجات المحلية لا تحمل أسعارًا أو باركودات مخمنة. السجلات القديمة لا تدخل المقارنة دون دليل مصدر وتاريخ حديث، وتُعاد تهيئة أسعار أساس المتابعة القديمة عند أول تحقق صالح دون إرسال خصم كاذب.

بطاقة المنتج تعرض الصورة والعبوة، ثم عروض المتاجر مرتبة حسب السعر. الأسعار عمرها أقل من 24 ساعة، وتظهر لحظة الجلب وحالة التوفر. السلة تجمع أسعار كل نطاق متجر/فرع منفصلًا، وتوضح المجموع الجزئي والرسوم المجهولة. نطاق الدانوب الحالي كتالوج إلكتروني غير مرتبط بفرع محلي مثبت.

الكتالوج المحلي ليس مصدر سعر. لا تزال ملفات بعض الموصلات القديمة تحتوي أمثلة غير مستخدمة؛ مدير الموصلات الإنتاجي يستبدلها بموصلات غير مهيأة ولا يقبل قراءاتها غير الموثقة.

## إعداد الخادم

GitHub Pages يستضيف الواجهة فقط. المتابعة في الخلفية تحتاج خادم HTTPS دائمًا مع قاعدة بيانات محفوظة.

1. ثبّت متطلبات `backend/requirements.txt` في بيئة Python 3.12.
2. انسخ `backend/.env.example` إلى `backend/.env` واضبط عنوان الموقع و`CORS_ORIGINS`.
3. من مجلد `backend` شغّل `python scripts/generate_push_keys.py` مرة واحدة. سينشئ ملفًا خاصًا محليًا، ويطبع المفتاح العام ومسار الملف الخاص فقط. انقل القيم إلى `.env` واضبط `VAPID_SUBJECT` ببريد تواصل حقيقي.
4. عيّن `ADMIN_TOKEN` عشوائيًا في بيئة الخادم فقط عند الحاجة لإجراءات الإدارة. لا تضع المفتاح الخاص أو رمز الإدارة في Flutter أو المستودع.
5. شغّل `uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000 --workers 1` خلف HTTPS. العامل الواحد مطلوب لأن جدول الفحص والجلسات الصوتية حاليًا داخل العملية. لتعدد العمال يجب فصل المجدول والجلسات وتطبيق قفل موزع.
6. اضبط نسخًا احتياطية لقاعدة البيانات. الترقية الحالية تضيف `baseline_version` تلقائيًا، ولا تحذف أصناف المستخدمين أو الأسعار القديمة؛ يمنع منطق الموثوقية استخدامها كأسعار مؤكدة.

خدمة الإشعارات تستعمل `pywebpush`، وتُسجل الرسالة «مرسلة» بعد قبول مزود الإشعارات فقط. القبول لا يضمن ظهورها على جهاز مغلق أو بلا اتصال. تبقى المحاولة الفاشلة معلقة حتى الفحص التالي (ضمن 24 ساعة)، وتُراجع صلاحية السعر والتوفر قبل المحاولة. ساعات الهدوء بتوقيت السعودية، والملخص اليومي غير متاح.

الفحص الدوري كل 30 دقيقة أثناء عمل الخادم. الأسعار ليست لحظية. يشترط التنبيه أن يثبت المصدر توفر الصنف وأن يتطابق الحجم والوحدة وعدد العبوات؛ لا يُفسر غياب المصدر على أنه سعر صفر. فحص المستخدم اليدوي مقيد بقائمته.

## بناء الواجهة ونشرها

```bash
cd frontend
flutter pub get
flutter analyze
flutter test
flutter build web --release --base-href /magadi_awfar/ --dart-define=API_BASE_URL=https://YOUR-SERVER.example/api/v1
```

استبدل عنوان المثال بعنوان الخادم الحقيقي، ثم انشر **محتويات** `frontend/build/web` بآلية GitHub Pages المستخدمة للمشروع. عند عدم توفير `API_BASE_URL` تعمل السلة والكتالوج محليًا والبحث المباشر عند توفره، لكن لا تعمل المتابعة الدورية أو Push. قيمة API_BASE_URL علنية وليست مكانًا للأسرار.

ملف `flutter_bootstrap.js` يترك نطاق Service Worker لخدمة التنبيهات. `sw_push.js` يفتح تبويب مقاضي البيت عند الضغط على الإشعار، داخل مسار التطبيق نفسه. لا يستعمل مسارًا مطلقًا غير موجود أو رابطًا قادمًا من جهة خارجية.

على الآيفون، أضف التطبيق إلى الشاشة الرئيسية وافتحه منها ثم اضغط «تفعيل». بعد حفظ الاشتراك في الخادم، استخدم «تجربة تنبيه» من سجل الإشعارات. لا يُعرض نجاح عندما يرفض الخادم الاشتراك أو يفشل الإرسال.

## حدود الاختبار والتشغيل

الاختبارات تستخدم مصادر وأسعارًا اصطناعية معزولة داخل ملفات الاختبار فقط؛ لا تُنشر هذه البيانات للزوار. تتضمن عزل جلسات الأجهزة، فشل المصدر، الأحجام والعبوات، إعادة تهيئة الأسعار القديمة، انتظار ساعات الهدوء وإعادة إرسال الرسائل، ومقاسات واجهة 320 و390 و1100 بكسل. لم يُختبر إرسال إلى جوال فعلي دون إعداد خادم ومفاتيح واشتراك حقيقي.

جلسة الضيف سر عشوائي محفوظ في المتصفح. مسح بيانات الموقع يفقد ارتباط الجهاز بقائمته على الخادم؛ لا توجد استعادة حساب بعد. لا تسجل ترويسة Authorization أو معاملات device_uuid/session_id في سجلات وسيط الإنتاج. الجلسات الصوتية على الخادم مؤقتة حتى إعادة تشغيله، بينما السلة الرئيسية محفوظة محليًا.

ربط كل متجر إضافي يتطلب مصدر بيانات مسموحًا ومستقرًا يثبت المنتج/الباركود والحجم والمخزون ونطاق الفرع. لا يحول هذا التحديث التطبيقات غير المربوطة إلى تكاملات فعلية.
